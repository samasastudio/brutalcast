What is Generative UI?

  • Intent-Based

    Interfaces generated in real-time response to user needs. The system adapts to the question, not the other way around.

  • Component-Driven

    AI orchestrates a trusted Design System, assembling pre-built, tested components into new layouts.

  • Ephemeral

    The interface is transient. It exists only to answer a specific query, then disappears.

Step 3: The Prompt Strategy

We Don't Generate HTML

Generating raw HTML is risky and unmaintainable. Instead, we ask the LLM to generate a Plan using a strict component registry.

We feed the prompt three key things:

  • Role: "You are a UI Generator."
  • Registry: List of valid components.
  • Context: The raw data we just fetched.
// System Prompt You are a UI generator. const AVAILABLE_COMPONENTS = [ 'BAR_CHART', 'WEATHER_CARD', 'ALERT_BANNER' ]; // Constraints 1. Return ONLY JSON. 2. Do not hallucinate props. 3. Use the provided data context.

Step 3b: The Schema Contract

1. Define & Inject

We use Zod to define the strict shape of our UI. This schema is converted to JSON and fed to the LLM as the "ground truth."

import { z } from "zod"; const PlanSchema = z.object({ layout: z.enum(["row", "grid"]), components: z.array(z.object({ type: z.enum(["BAR_CHART", "CARD"]), props: z.record(z.any()) })) });

2. Validate Output

We never trust the AI blindly. We parse the output against our schema to catch hallucinations before they break the UI.

const raw = await llm.generate(prompt); const result = PlanSchema.safeParse(raw); if (!result.success) { // Fallback or Retry return <ErrorUI />; }

Step 4: The LLM Response

{ "layout": "comparison_view", "components": [ { "type": "BAR_CHART", "props": { "title": "Temp Comparison", "data": [ { "city": "Austin", "val": 85 }, { "city": "London", "val": 62 } ] } } ] }

Structured Output

The LLM returns a clean JSON object. It selects the BAR_CHART component because the user's intent was to "compare".

It automatically maps the raw weather data into the props structure required by our chart component.

Step 5: Component Router

The Safety Layer

This is where the magic happens. We map the JSON plan to actual, compiled React components.

This ensures Type Safety and Design Consistency. The LLM creates the structure; our code handles the rendering.

const COMPONENT_MAP = { BAR_CHART: dynamic(() => import('./BarChart')), WEATHER_CARD: dynamic(() => import('./Card')) }; export function RenderPlan({ plan }) { return plan.components.map(comp => { const Component = COMPONENT_MAP[comp.type]; return <Component {...comp.props} />; }); }

Trade-offs & Mitigations

Challenges

  • Latency: LLM inference adds 1-3s overhead.
  • Determinism: AI might pick the wrong chart.
  • Security: Injection attacks via props.

Mitigations

  • Streaming: Show skeleton UI immediately.
  • Zod Schema: Strictly validate JSON output.
  • Whitelisting: Only allow registered components.

Strategic Value

Engineering Velocity

Shift focus from building single-purpose pages to building capabilities. The UI constructs itself based on the data available.

Adaptability

The interface adapts to user context automatically. "Show me high-priority alerts" renders a different view than "Show me historical trends."

Maintenance

Logic lives in the orchestration layer, not the view layer. You maintain a stable set of dumb components while the AI handles the glue code.
